# Аудит: соответствие заданию и история трёх версий

Проверка не по наличию кода, а по фактическому поведению. Отметка «проверено» означает, что
поведение подтверждено автоматическим тестом либо запуском приложения в браузере (или тем и другим).

**Прогон верификации на момент сдачи:** `npm run typecheck` — без ошибок, `npm run lint` — 0 ошибок
и предупреждений, `npm run test` — 112 тестов в 9 файлах пройдены, `npm run build` — сборка успешна
(46 модулей, 296 КБ JS до сжатия).

Связанные документы: [CHECKLIST.md](CHECKLIST.md) — ручные сценарии проверки,
[docs/reviews.md](docs/reviews.md) — три цикла независимого ревью, вкладка «AI Worklog» в самом
приложении — процесс разработки.

### Замечание третьего ревью — закрыто в v3.1

Единственное, что оставалось открытым после третьего ревью, относилось к демонстрационным данным:

> Демо-набор не показывает состояния «ждёт свободного места» и «размещение требует пересмотра»:
> мест 14 на 8 заявок, дефицита штатными действиями не создать, а сдвинуть дату из интерфейса
> нельзя. Оба состояния работают и покрыты тестами, но увидеть их можно только подменив
> сохранённое состояние вручную.

| Что сделано | Чем подтверждено |
| --- | --- |
| Пара заявок «Сырость Тина» и «Водяной Прохор» с требованием влажности от 85 %: такая влажность есть только в склепе вместимостью 1. Тина занимает его по более близкому сроку, Прохор остаётся ждать | Тест «состояние "ждёт свободного места" видно на демо-наборе»: `awaitingCapacity === 1`, у записи Прохора `unplacedReason === 'awaiting_capacity'` и в `blockedByCapacity` ровно склеп |
| Заявка «Смотритель Аркадий», размещённая оператором вручную в стартовом состоянии, со сроком, истёкшим после назначения. Автопрогон решения человека не трогает, поэтому размещение сохраняется — но больше не проходит условия | Тест «состояние "размещение требует пересмотра" видно на демо-наборе»: `needsReview === 1`, балл 0 и в сводке, и в карточке |
| Побочный эффект: просрочены теперь двое — Марфа без места и Аркадий с местом | Тест «счётчики просроченных различаются на демо-наборе, а не совпадают случайно»: `overdueTotal === 2`, `overdueUnplaced === 1`. Раньше эти счётчики на демо совпадали, и ошибка в них маскировалась |

Алгоритм подбора, формула балла и правила приоритета не менялись: средний балл размещений без
нарушений остался прежним — 92. **Открытых замечаний не осталось.**

## 3. Доменные инварианты

| Инвариант | Проверено | Чем |
| --- | --- | --- |
| Блокирующий конфликт нельзя компенсировать баллом | да | тест: у несовместимого места `score === 0` при `breakdown.total === 100` |
| Занятость никогда не превышает вместимость | да | тест последовательных назначений + `assertCapacityInvariant` |
| Просроченная заявка не назначается никуда | да | тест с `confirmed: true` — назначение всё равно отклонено |
| Ручное и автоматическое назначение проходят одну проверку | да | обе ветки вызывают `validateAssignment` внутри `assign()` |
| Назначение с предупреждениями требует подтверждения | да | тест: без `confirmed` — отказ, с `confirmed` — успех |
| Распределение детерминировано | да | тест: повторный прогон даёт тот же результат |
| Решение оператора не переписывается, решение системы пересматривается | да | тесты `skippedManual` для `manual` и пересчёта для `accepted` |
| Заявка не блокирует сама себя на своём же месте | да | тест повторной проверки собственного места при полной занятости |
| Сводка и карточка не могут разойтись в оценке | да | тест сравнивает значение из отчёта со значением из `explainExistingAssignment` |
| Объяснение не приписывает одному месту данные другого | да | 4 теста: корневая причина без чисел при разных данных, дословная — при одинаковых |

Отдельно: неуязвимость домена проверялась внешним фаззингом на 4 000 случайных вызовов `assign()`
во всех трёх циклах ревью — 723 принятых назначения, 3 277 отклонённых, ни одного нарушения.

## 4. Честность отчётных данных

Метрики в AI Worklog перепроверялись на аудите и исправлялись по фактическим данным:

- время третьей версии сначала было записано как «около 25 минут», но метки файлов показали два
  окна работы с перерывом между сессиями — запись заменена на сумму окон с оговоркой, что интервал
  по часам временем работы не является;
- размер сборки приведён к фактическому выводу `vite build`, а не к записанному по памяти;
- расход токенов помечен как счётчик бюджета контекста, а не биллинговая статистика: таких данных
  среда не предоставляет;
- раздел «что делал человек / что делал AI» переписан перед сдачей: первая редакция приписывала
  человеку восемь инженерных решений, хотя фактически человек задал ТЗ, уточнил язык и организовал
  три цикла проверки. Это было замечанием первого ревью, и оно учтено.

## 5. Что осталось за рамками проверки

- Сценарий отказа localStorage при записи (переполнение квоты) обрабатывается в коде, но
  искусственно не воспроизводился.
- Скачивание резервной копии проверено на появление кнопок и на удаление копии; сам файл в jsdom
  не сохраняется, поэтому загрузка проверена только в браузере визуально.
- Отдельных тестов на компоненты `ReportView` и `LocationsView` нет — они проверены сценарно
  через `app.test.tsx` и вручную.
- Клавиатурная навигация доведена для вкладок; список заявок управляется мышью и обычным Tab.
- Скринридеры: роли и ARIA-связи проверены в DOM и тестами, с реальным NVDA / VoiceOver
  приложение не тестировалось.
- Фаззинг, которым ревью проверяло неуязвимость домена, в репозиторий не добавлен: он остаётся
  внешним инструментом проверки, а не частью поставки.
